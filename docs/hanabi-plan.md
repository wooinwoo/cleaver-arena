# 하나비(Hanabi) 기획서

## 1. 개요

- 인원: 2–5인 (2–3인 최적)
- 시간: 약 25분
- 장르: 협력 추리. 탈락자 없음, 전원 한 팀
- 컨셉: 불꽃 축제 전날. 모두가 힘을 합쳐 5색 불꽃을 1→5 순서대로 완성한다.
  단, 자기 패는 볼 수 없고 남의 패만 보인다 (인디언포커와 같은 view 구조 재사용)

## 2. 공식 룰 정리 (Antoine Bauza, 2013 SDJ)

### 2.1 구성

- 50장: 5색(빨·노·초·파·백) × {1×3장, 2·3·4×2장, 5×1장}
- 2–3인: 1인당 5장 / 4–5인: 1인당 4장. 패는 뒷면으로 들고(자신만 못 봄)
- 힌트 토큰 8개, 실수(퓨즈) 토큰 3개, 색별 완성 더미 5개

### 2.2 턴 행동 (3택 1)

1. **힌트 주기** (토큰 1 소모, 0개면 불가): 다른 플레이어 1명을 골라
   "이 색" 또는 "이 숫자" 중 하나를 선언 → 해당되는 그 사람 패를 전부 가리킴.
   색 힌트면 색만, 숫자 힌트면 숫자만 알려준다. 거짓 힌트 금지(해당 카드가 1장 이상 있어야 함)
2. **버리기**: 자기 패 1장을 버림 더미로 → 힌트 토큰 1 회복(최대 8). 버린 자리에 덱에서 보충
3. **내기**: 자기 패 1장을 골라 색 더미에 올리기 시도
   - 더미의 다음 숫자(1부터 시작, 1→2→…→5)와 일치 → 성공. 5 완성 시 힌트 토큰 1 회복
   - 불일치 → 실수 +1, 그 카드는 버림. 실수 3개째면 즉시 게임 종료

### 2.3 종료와 점수

- 실수 3개: 즉시 종료. 점수 = 각 색 더미의 top 숫자 합
- 덱 소진: 덱이 빈 뒤 각자 마지막 1턴씩 → 종료. 같은 방식으로 합산
- 만점 25점. 참고 랭크: ~5 혹평, ~10 보통, ~15 respectable, 20+ 대단, 25 전설 (맛보기 문구로만 사용)

## 3. 플랫폼 매핑

### 3.1 `shared/hanabi.ts`

```ts
type HanabiCard = { id: string; color: 0|1|2|3|4; num: 1|2|3|4|5 };
interface HanabiState extends BaseState {
  kind: 'hanabi';
  deck: HanabiCard[];            // 서버만 보유
  hands: HanabiCard[][];         // seat별
  piles: number[];               // 색별 완성 top (0 = 빈 더미)
  hints: number;                 // 남은 힌트 토큰 (0–8)
  fuses: number;                 // 실수 (0–3)
  finalTurns: number | null;     // 덱 소진 후 남은 턴 수 (null = 진행 중)
}
```

- `act`: `{type:'hint', target, hint:'color'|'num', value}` /
  `{type:'discard', index}` / `{type:'play', index}`
- 검증 포인트: 힌트 토큰 잔량, 거짓 힌트 금지(해당 없음), index 범위,
  낸 카드의 순서 일치 여부, 종료 조건(실수3 / finalTurns 소진)
- `view(seat)`: 자기 패는 `{num:null, color:null}` 뒷면으로,
  남 패·더미·토큰·버림더미(선택: 공개 정보이므로 포함)는 그대로.
  힌트 로그는 `log`에 누적 (누가 누구에게 무슨 힌트를 줬는지 전체 공개)

### 3.2 서버 (`server/tabletop.ts` definitions 한 줄)

- `hanabi: (seats) => runtime(createHanabi(seats), actHanabi, hanabiView)`
- 2–5인. AI 대전은 중 난이도부터(아래 참조). 관전 view는 전원 패 공개

### 3.3 클라이언트 (`src/tabletop.ts` drawHanabi)

- 내 패: 뒷면 카드 + "힌트받은 정보" 뱃지(색/숫자 알려짐 표시 — 서버가 알려준 것만)
  - 구현 단순화안: 힌트받은 카드만 작은 색/숫자 칩으로 표시 (view에 `known: {color?, num?}[]` 포함)
- 남 패: 앞면 그대로. 클릭 → 힌트 주기(색 5종/숫자 5종 버튼) / 내 턴에 내기·버리기는 내 뒷면 카드 클릭
- 상단: 색별 완성 더미(1→5 진행), 힌트 토큰 ●×8, 실수 ✕×3
- 액션바/툴바 패턴은 기존 보드게임과 동일 (쿠데타·다빈치 선례 따름)

### 3.4 view 확장 (힌트받은 정보)

```ts
// view(seat)의 내 패 항목: { id, color: null, num: null, known: { color?: number; num?: number } }
```

서버가 힌트를 줄 때 해당 카드의 known에 기록. AI와 클라가 같은 정보를 본다.

## 4. AI 설계 (상·중·하)

기준은 실전 검증된 H-Group 컨벤션(hanabi.github.io) Level 1 subset이다.
용어: chop = 가장 오른쪽의 힌트없는 카드(버릴 카드), focus = 힌트가 가리키는 1장.

- **하**: 합법 랜덤 (내기/버리기/가능하면 힌트 중 랜덤). 가끔 5를 버리는 맛
- **중**: 약속 2개만 지킨다.
  1. Play 약속: 힌트받은 카드 중 더미 다음 숫자와 일치 확정 → 내기
  2. 버리기는 chop(가장 오래된 힌트없는 카드)부터. 죽은 카드(완성 색/숫자) 우선
  3. 낼 수 있는 카드가 보이는 동료에게 힌트 주기 (토큰 있을 때)
- **상**: 중 + 세이브 3종.
  - 5 세이브: chop 위의 5에게 숫자 힌트 (색 힌트면 Play 약속이 되므로 숫자만)
  - 2 세이브: 유일하게 남은 2에게 숫자 힌트
  - 크리티컬 세이브: 남은 매수 1장뿐인 카드에게 색/숫자 힌트
  - chop에 세이브 대상이 있으면 Play 힌트보다 세이브 우선 (Save Principle)
  - 힌트 토큰 관리: 0개 방치 금지, 8개 꽉 채우기 전에 쓰기 (Minimum Clue Value)
  - 같은 known이면 남은 매수 기댓값으로 타이브레이크

구현 포인트: AI는 `known` + 공개 정보(버림더미, 완성 더미, 남 패)로
chop 위치·확정 playable·세이브 대상을 계산한다. 사람과 같은 정보만 쓴다.

서버 봇 드라이버(`driveBot` 패턴, stash에 구현됨)를 그대로 재사용.
테스트: `aiHanabi` 합법성 N회 + 봇끼리 완주(25점 만점에 10점대 후반이면 합격선).

## 4-2. 초보자 보조 UI (H-Group을 화면에 이식)

위 약속을 사람 플레이어에게도 보여주면 입문 장벽이 사라진다.

- 내 패 chop(버릴 카드) 위치에 작은 표시: "버리면 이 카드가 나감"
- Play 약속 카드(힌트로 낼 수 있음이 확정)에 초록 테두리
- 세이브 대상(5·유일 2·크리티컬)이 chop에 있으면 노란 테두리 + "버리면 안 됨"
- 힌트 주기 모드에서 카드를 고르면 "Play 약속"/"세이브" 중 뭘로 읽히는지 미리보기
- `known` 칩은 기존 기획(4.1절 아님, 3.3절)대로 유지

이 보조 UI는 on/off 토글을 둔다 (고수는 끄고 함).

## 6. 미정 사항 (확정)

- 버림더미 공개: 공식대로 공개. view에 `discards` 포함 (버린 카드 확인 가능)
- 2인 변형 없음 (공식 그대로 5장씩)
- 레인보우/변형 규칙 없음. 기본판만

## 7. 화면·플로우 상세

### 7.1 레이아웃 (위→아래)

1. **완성 더미줄**: 5색 × 현재 top 숫자. 완성된 색은 불꽃 마크
2. **토큰줄**: 힌트 ●×8, 실수 ✕×3 (남은 것만 밝게)
3. **남 패역**: 좌석별 가로 패. 내 턴에 힌트 주기 모드면 클릭 가능 + focus 미리보기
4. **내 패역**: 뒷면 5장 + known 칩 + chop/Play/세이브 테두리(4-2절)
5. **액션바**: [힌트 주기] [내기] [버리기] — 내 턴에만 활성화. 힌트 토큰 0이면 힌트 버튼 비활성화 + 이유 표시

### 7.2 힌트 주기 플로우 (3스텝)

1. 남 패에서 대상 좌석 클릭 → 2. 색 5종/숫자 5종 중 선택 (해당 없는 건 비활성화) →
3. focus 카드에 "Play 약속"/"세이브" 뱃지 미리보기 → 확정
- 거짓 힌트(해당 카드 0장)는 선택지에서 막는다 (서버도 거부)

### 7.3 종료 연출

- 실수 3: 폭죽 폭발 연출 + "X점으로 종료" + 랭크 문구
- 덱 소진: "마지막 바퀴" 배너 + 남은 턴 수 표시 → 종료 시 점수 + 랭크
- 랭크 문구: 0–5 "불꽃이 안 터졌어요", 6–10 "조금 아쉬워요", 11–15 "훌륭해요",
  16–20 "대단해요", 21–24 "전설 코앞!", 25 "완벽한 불꽃!"
- 효과음은 기존 `sound()` 재사용 (성공 ascending / 실수 low)

## 8. 엣지케이스·관전·인원별

- 토큰 8개 가득 + 버리기: 허용하되 회복 없음 (공식 그대로)
- 힌트 토큰 0 + 낼 카드 없음 + 버릴 카드가 전부 세이브 대상: 실전 데드락은
  거의 없지만, 발생 시 `pass` 불가 → 세이브 중 가장 덜 아까운 것(2 > 크리티컬 > 5 순 포기)을
  버리라고 안내. 서버는 강제하지 않음 (사람 판단)
- 관전: 전원 패 앞면 공개 + 힌트 로그 실시간. ready 버튼 숨김 (스플렌더 선례)
- 2인전: 5장씩, 힌트 압박이 셈. AI 대전은 2인(human+bot) 고정
- 방 정원: `TABLE_GAMES` min 2, max 5. 공개방·초대·코드 흐름은 전 게임 공통

## 9. 테스트 시나리오

### 단위 (`tests/hanabi.test.ts`)

- 초기 분배: 2–3인 5장, 4–5인 4장, 덱 잔량, 토큰 8/실수 0
- 힌트: 토큰 차감, 거짓 힌트 거부, 토큰 0 거부
- 내기: 순서 일치 성공, 불일치 실수+버림, 5 완성 토큰 회복
- 버리기: 토큰 회복(상한 8), 보충, 덱 소진 시 미보충
- 종료: 실수 3 즉시 종료, 덱 소진 후 N턴 종료, 점수 합산
- view: 자기 패 숨김 + known만 노출, 남 패 공개, 관전(seat -1) 전원 공개

### 브라우저 (`tests/hanabi-browser.ts`)

- 입장 → 2인 방 → 준비 → 내 턴에 힌트 주기 → 상대 내기 → 점수 반영 확인
- 종료까지 봇 대전 1판 완주 (issons AI `low`로 시간 단축)
- 390×844·768×1024 겹침/잘림 검사 (responsive 패턴 재사용)
