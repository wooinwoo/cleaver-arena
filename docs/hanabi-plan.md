# 하나비(Hanabi) 기획서

## 1. 개요

- 인원: 2–5인 (2–3인 최적)
- 시간: 약 25분
- 장르: 협력 추리. 탈락자 없음, 전원 한 팀
- 컨셉: 불꽃 축제 전날. 모두가 힘을 합쳐 5색 불꽃을 1→5 순서대로 완성한다.
  단, 자기 패는 볼 수 없고 남의 패만 보인다 (인디언포커와 같은 view 구조 재사용)

## 2. 공식 룰 정리 (Antoine Bauza, 2013 SDJ)

### 2.1 구성

- 50장: 5색(빨·노·초·파·백) × {1×3장, 2·3·4×2장, 5×1장}
- 2–3인: 1인당 5장 / 4–5인: 1인당 4장. 패는 뒷면으로 들고(자신만 못 봄)
- 힌트 토큰 8개, 실수(퓨즈) 토큰 3개, 색별 완성 더미 5개

### 2.2 턴 행동 (3택 1)

1. **힌트 주기** (토큰 1 소모, 0개면 불가): 다른 플레이어 1명을 골라
   "이 색" 또는 "이 숫자" 중 하나를 선언 → 해당되는 그 사람 패를 전부 가리킴.
   색 힌트면 색만, 숫자 힌트면 숫자만 알려준다. 거짓 힌트 금지(해당 카드가 1장 이상 있어야 함)
2. **버리기**: 자기 패 1장을 버림 더미로 → 힌트 토큰 1 회복(최대 8). 버린 자리에 덱에서 보충
3. **내기**: 자기 패 1장을 골라 색 더미에 올리기 시도
   - 더미의 다음 숫자(1부터 시작, 1→2→…→5)와 일치 → 성공. 5 완성 시 힌트 토큰 1 회복
   - 불일치 → 실수 +1, 그 카드는 버림. 실수 3개째면 즉시 게임 종료

### 2.3 종료와 점수

- 실수 3개: 즉시 종료. 점수 = 각 색 더미의 top 숫자 합
- 덱 소진: 덱이 빈 뒤 각자 마지막 1턴씩 → 종료. 같은 방식으로 합산
- 만점 25점. 참고 랭크: ~5 혹평, ~10 보통, ~15 respectable, 20+ 대단, 25 전설 (맛보기 문구로만 사용)

## 3. 플랫폼 매핑

### 3.1 `shared/hanabi.ts`

```ts
type HanabiCard = { id: string; color: 0|1|2|3|4; num: 1|2|3|4|5 };
interface HanabiState extends BaseState {
  kind: 'hanabi';
  deck: HanabiCard[];            // 서버만 보유
  hands: HanabiCard[][];         // seat별
  piles: number[];               // 색별 완성 top (0 = 빈 더미)
  hints: number;                 // 남은 힌트 토큰 (0–8)
  fuses: number;                 // 실수 (0–3)
  finalTurns: number | null;     // 덱 소진 후 남은 턴 수 (null = 진행 중)
}
```

- `act`: `{type:'hint', target, hint:'color'|'num', value}` /
  `{type:'discard', index}` / `{type:'play', index}`
- 검증 포인트: 힌트 토큰 잔량, 거짓 힌트 금지(해당 없음), index 범위,
  낸 카드의 순서 일치 여부, 종료 조건(실수3 / finalTurns 소진)
- `view(seat)`: 자기 패는 `{num:null, color:null}` 뒷면으로,
  남 패·더미·토큰·버림더미(선택: 공개 정보이므로 포함)는 그대로.
  힌트 로그는 `log`에 누적 (누가 누구에게 무슨 힌트를 줬는지 전체 공개)

### 3.2 서버 (`server/tabletop.ts` definitions 한 줄)

- `hanabi: (seats) => runtime(createHanabi(seats), actHanabi, hanabiView)`
- 2–5인. AI 대전은 중 난이도부터(아래 참조). 관전 view는 전원 패 공개

### 3.3 클라이언트 (`src/tabletop.ts` drawHanabi)

- 내 패: 뒷면 카드 + "힌트받은 정보" 뱃지(색/숫자 알려짐 표시 — 서버가 알려준 것만)
  - 구현 단순화안: 힌트받은 카드만 작은 색/숫자 칩으로 표시 (view에 `known: {color?, num?}[]` 포함)
- 남 패: 앞면 그대로. 클릭 → 힌트 주기(색 5종/숫자 5종 버튼) / 내 턴에 내기·버리기는 내 뒷면 카드 클릭
- 상단: 색별 완성 더미(1→5 진행), 힌트 토큰 ●×8, 실수 ✕×3
- 액션바/툴바 패턴은 기존 보드게임과 동일 (쿠데타·다빈치 선례 따름)

### 3.4 view 확장 (힌트받은 정보)

```ts
// view(seat)의 내 패 항목: { id, color: null, num: null, known: { color?: number; num?: number } }
```

서버가 힌트를 줄 때 해당 카드의 known에 기록. AI와 클라가 같은 정보를 본다.

## 4. AI 설계 (상·중·하)

하나비 완전체는 학회급 난제이므로, 실용적 컨벤션 AI로 간다.

- **하**: 합법 랜덤 (내기/버리기/가능하면 힌트 중 랜덤). 가끔 5를 버리는 맛
- **중**: 기본 정석만.
  - 낼 수 있음이 확정된 카드(known이 더미 다음 숫자와 일치) → 내기
  - 아니면: 힌트 토큰이 있고, 낼 수 있는 카드를 가진 동료가 있으면 그 힌트 주기
  - 아니면: 힌트받은 적 없는 가장 오래된 카드 버리기
- **상**: 중 + 아래 추가.
  - 5·위험카드(남은 매수 1장뿐인 카드) 보호: 그런 카드를 든 동료에게 힌트로 세이브
  - 버릴 때: 이미 완성된 색/숫자(죽은 카드) 우선 버리기
  - 힌트 토큰 관리: 0개 방치 금지, 8개 꽉 채우기 전에 쓰기
  - 같은 known이면 점수 기댓값(남은 매수)으로 타이브레이크

서버 봇 드라이버(`driveBot` 패턴, stash에 구현됨)를 그대로 재사용.
테스트: `aiHanabi` 합법성 N회 + 봇끼리 완주(25점 만점에 10점대 후반이면 합격선).

## 6. 미정 사항 (구현 시 확정)

- 버림더미 공개 여부: 공식은 공개(버린 카드 확인 가능). view에 `discards: number[]` 포함으로 결정
- 2인 변형 없음 (공식 그대로 5장씩)
- 레인보우/변형 규칙 없음. 기본판만
