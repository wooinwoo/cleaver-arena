# 스플렌더 규칙과 실행 검증

현재 구현은 2–4인 스플렌더 기본판이다. 공식 기본판 규칙, 카드 수치, 서버 상태 전이, 실제 브라우저 경기를 대조했다. 검증한 범위에서 경기 진행을 막거나 승자를 잘못 정하는 추가 결함은 발견하지 못했다. 마지막 라운드에서 접속 종료로 경기가 끝났을 때 안내 문구가 남는 오류 한 건을 수정했다.

## 적용 판본

기준은 SPACE Cowboys의 2024 개정 영문 기본판 규칙이다. 현재 공식 제품 페이지가 연결하는 PDF를 확인했고, 2014판과 설명 차이가 있는 항목도 비교했다.[^1][^2] 2인으로 시작해도 별도 제품인 Splendor Duel 규칙으로 바뀌지 않는다. 확장판도 포함하지 않는다.[^3]

2024판은 공급처에 색이 부족할 때 1–2개를 가져오는 조건, 보유 중인 색 보석 대신 황금을 지불할 수 있다는 점, 완전 동점의 공동 승리를 명시한다. 구현은 이 설명을 따른다.[^1] 2014판의 개요 문장만 읽으면 15점 즉시 종료처럼 보일 수 있지만, 해당 판본의 마지막 종료 절도 동일한 차례 수를 요구한다.[^2]

공식 사이트의 대회 가이드도 별도로 확인했다. 그 문서의 45분 제한, 대회 참가 인원, 추가 순위 결정 조건은 대회 운영 규정이다. 일반 기본판에 적용하지 않았다. 링크의 언어 표시는 English지만 연결된 문서 본문은 프랑스어였다.[^4]

## 규칙 대조

| 항목 | 적용 기준 | 검증 결과 |
|---|---|---|
| 카드 구성 | 1/2/3단계 40/30/20장[^1] | 총 90장, 단계와 색 분포 일치 |
| 초기 시장 | 단계별 공개 카드 4장[^1] | 인원별 초기화, 구매·예약 후 보충 통과 |
| 공급처 | 2/3/4인 색별 4/5/7개, 황금 5개[^1] | 세 인원수 모두 통과 |
| 귀족 배치 | 참가 인원 + 1명[^2] | 초기화와 시뮬레이션 보존 검사 통과 |
| 서로 다른 보석 | 3색, 부족하면 가능한 색 모두[^1] | 공급량과 선택량 759,375개 조합 일치 |
| 같은 보석 | 가져오기 전 4개 이상일 때 2개[^1] | 재고 3개와 4개 경계 통과 |
| 황금 획득 | 예약 시 공급처에 있으면 1개[^1] | 황금 소진 상태의 예약도 통과 |
| 예약 | 공개 카드 또는 더미 맨 위, 최대 3장[^2] | 상대 예약 구매·네 번째 예약 거부 |
| 예약 해제 | 구매로만 손에서 제거[^2] | 임의 폐기 행동 거부 |
| 카드 구매 | 공개 카드 또는 자신의 예약 카드[^2] | 두 경로, 무료 구매, 더미 소진 통과 |
| 영구 할인 | 소유 카드당 같은 색 비용 1 감소[^2] | 90장 전체에 할인 0/1/3개를 적용해 검사 |
| 황금 지불 | 색 보석을 보유해도 대체 가능[^1] | 직접 입력한 대체 지불 200개 사례 통과 |
| 보석 한도 | 황금 포함 차례 끝 정확히 10개 이하[^2] | 초과분 선택·반납 중 다음 행동 차단 |
| 반납 대상 | 이번에 받은 보석도 반납 가능[^2] | 방금 예약으로 받은 황금 반납 통과 |
| 귀족 방문 | 보석이 아닌 할인 조건, 차례당 최대 1명[^2] | 자동 방문·여러 귀족 선택·미충족 거부 |
| 종료 시점 | 15점 도달 후 모두 같은 차례 수[^2] | 모든 좌석의 종료 경계, 귀족으로 15점 통과 |
| 승자 | 최고 점수, 동점이면 구매 카드가 적은 사람[^2] | 후순서 역전·동점 판정 통과 |
| 완전 동점 | 해당 참가자만 공동 승리[^1] | 4인 중 2명만 공동 승리하는 상태 통과 |

카드 수치는 두 별도 공개 전사 자료의 단계·색·점수·비용을 모두 정규화해 현재 데이터와 비교했다. 90장 전부 일치했다.[^5][^6] 이는 두 전사 자료와의 일치 증거이며, 제조사가 배포한 90장 전체의 기계 판독 데이터와 대조한 것은 아니다. 귀족은 4+4 조건 다섯 종류와 3+3+3 조건 다섯 종류를 사용한다.

## 방에서 적용하는 예외

다음은 오프라인 기본판 자체의 규칙과 구분해야 한다.

- 선공은 나이 대신 방장이다. 방 규칙과 README에 표시한다.
- 획득·구매·예약이 전부 불가능할 때만 패스를 허용한다. 전원이 연속으로 불가능하면 무승부로 종료한다. 공식 기본판과 대회 문서에서 이 교착 처리 조항은 확인하지 못했으므로 방의 진행 예외로 표시한다.
- 접속이 끊기면 행동을 멈추고 재접속을 기다린다. 명시적 퇴장 또는 재접속 만료 시 남은 접속자가 한 명이면 승리, 여러 명이면 무승부로 해당 경기를 끝낸다. 인원을 줄인 새 경기는 다시 준비해서 시작한다. 진행 중 인원에 맞춰 보석을 재분배하지 않는다.
- 별도 턴 시간제한은 없다. 연결을 유지한 참가자가 선택하지 않으면 그 참가자의 행동을 기다린다.

## 실행 증거

최신 전체 자동 테스트는 **90개 통과, 실패 0개**다. 스플렌더 외 문도피구·오목·쿼리도·십이장기·체스·인디언포커의 기존 로직과 네트워크 검사도 포함한다. 프로덕션 빌드와 TypeScript 검사도 통과했다.

추가로 오목·쿼리도·동물장기·인디언포커 파티룰·체스·더 지니어스 십이장기의 PC/모바일 브라우저 종료·재경기 검사도 다시 통과했다. 오목과 문도피구는 TCP 통신이 응답 없이 끊어진 상황에서 같은 방과 세션으로 복귀하는 브라우저 검사를 통과했다.

스플렌더의 상세 증거는 다음과 같다.

| 검사 | 실행 결과 | 한계 또는 의미 |
|---|---|---|
| 보석 선택 독립 판정 | 759,375개 조합 일치 | 재고 0–4와 선택 0–2의 모든 조합이며 전체 게임 상태 전수조사는 아님 |
| 90장 비용과 할인 | 정상 구매 260개, 황금 대체 200개 통과 | 할인 후 비용이 10개를 넘는 10개 구성은 구매 거부 확인 |
| 잘못된 입력 | 세 단계에서 198개 거부, 상태 불변 | 빈 값·타입 오류·음수·소수·NaN·무한대 포함 |
| 비공개 정보 | 2/3/4인 모든 관측 좌석 9개 통과 | 덱 순서와 상대 예약 내용을 바꿔도 해당 관측값 불변 |
| 결정적 완주 | 18경기, 1,519행동 | 매 행동 카드·보석·귀족 보존 및 직렬화 검사 |
| 실제 WebSocket 완주 | 3인 97행동, 4인 107행동 | 반납 중 재접속, 비밀 카드 복구, 종료·재경기 |
| 실제 브라우저 완주 | 2인 71행동, 3인 85행동, 4인 110행동 | 실제 로컬 서버에서 PC와 모바일 터치 문맥을 혼합 |
| 브라우저 단계 | 2인은 행동·반납, 3인은 행동·귀족, 4인은 세 단계 모두 | 종료 후 행동 차단, 준비, 새 경기 초기화도 확인 |
| 브라우저 화면 크기 | 너비 320/390/667/768/1280px 통과 | 가로 넘침, 시장 카드 수, 주요 영역 잘림 검사 |
| 희귀 UI 상태 | 390px와 1280px 모두 통과 | 제어된 WebSocket 상태와 실제 규칙 엔진으로 단계별 검사 |

희귀 UI 검사는 황금을 직접 선택하는 구매, 빈 값·소수·음수·초과 입력 차단, 서버 거부 후 재선택, 보석 10개 상태에서 예약, 방금 받은 황금 반납, 무료 예약 카드 구매를 포함한다. 두 귀족을 동시에 만족하는 상태에서 한 명만 선택하고 그 3점으로 마지막 좌석이 승리하는 경로도 검사했다. 반납 중 및 귀족 선택 중 새로고침 후 같은 결정을 이어갈 수 있었다.

별도의 독립 검토에서는 실제 서버에 중복 예약·반납 요청, 좌석 위조, 끊어진 참가자가 있는 동안의 행동, 잘못된 재접속 토큰, 동일 토큰의 동시 재접속을 보냈다. 중복 행동은 한 번만 반영됐고, 동시 재접속은 한 연결만 성공했다. 비밀 카드 복구와 3인 퇴장 후 2인 재경기 초기화도 통과했다.

희귀 UI 검사의 준비된 상태는 처음부터 정상 행동으로 도달한 경기 기록과 다르다. 실제 네트워크 완주 증거와 구분해 사용한다. 결정적 완주의 테스트 참가자는 운영 코드의 일부 계산 함수를 사용하므로 그 결과만으로 규칙 일치를 주장하지 않는다. 공식 규칙 대조, 별도의 보석 선택 판정, 실제 UI 입력 검사를 함께 사용한다.

## 수정한 오류

마지막 라운드 중 접속 종료로 승패가 정해지면 서버의 `winner` 또는 `draw`는 종료 상태가 되지만, 점수로 정한 공동 승자 배열은 비어 있을 수 있다. 화면은 이 배열만 보고 진행 중인 마지막 라운드 안내를 표시했다. 실제 승패는 정해져 있고 행동도 막혀 있지만 안내가 모순됐다.

종료 문구를 `winner`와 `draw`로 판단하도록 한 줄 수정했다. 수정 전 브라우저 검사는 “경기 종료” 대신 “마지막 라운드”를 받아 실패했다. 수정 후 PC·모바일 검사 모두 통과했다. 게임 규칙이나 점수 계산은 바꾸지 않았다.

## 재실행

프로젝트 디렉터리에서 다음 명령을 실행한다. 브라우저 검사는 기본적으로 `http://127.0.0.1:3186`의 실행 중인 로컬 서버를 사용한다.

```bash
npm test
npm run build
npm run test:splendor
npm run test:splendor:edges
```

일반 완주는 `tests/splendor-browser.ts`, 희귀 화면 단계는 `tests/splendor-edge-browser.ts`, 추가 규칙 검사는 `tests/splendor-audit.test.ts`에 남겼다. Playwright는 Chromium과 모바일 터치·뷰포트 에뮬레이션을 사용한다. 실제 iPhone Safari·Android 실기기, 모든 네트워크 지연 조건, 장시간 부하, 가능한 전체 게임 상태에 대한 무결함 증명은 포함하지 않는다.
